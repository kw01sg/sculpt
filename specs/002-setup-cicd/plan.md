# Implementation Plan: CI/CD Pipeline Setup

**Branch**: `002-setup-cicd` | **Date**: 2026-06-08 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-setup-cicd/spec.md`

## Summary

Set up automated CI/CD for the Sculpt application using Railway's native GitHub App for continuous delivery (three environments: Production, Develop, PR Preview) and GitHub Actions for continuous integration quality gates (black/ruff lint, frontend build check). Three code changes are required: a new GitHub Actions workflow file, an nginx.conf proxy update for Railway's internal network, and a backend Dockerfile CMD update to run migrations on startup.

## Technical Context

**Language/Version**: Python 3.11 (backend), Node 18 / TypeScript (frontend), YAML (GitHub Actions workflows)
**Primary Dependencies**: Railway GitHub App (native CD), GitHub Actions (CI quality gates), Nginx (frontend production server), Alembic (migrations on startup)
**Storage**: Supabase PostgreSQL — two instances: `sculpt-prod` (production) and `sculpt-dev` (develop + PR previews)
**Testing**: black + ruff (backend linting), npm run build (frontend compile check) — no test suite in scope for this feature
**Target Platform**: GitHub Actions runners (ubuntu-latest) for CI; Railway cloud for CD
**Project Type**: DevOps / Infrastructure (CI/CD pipeline for a web application)
**Performance Goals**: Deployments complete within 10 minutes of trigger (SC-002, SC-003)
**Constraints**: Railway free/hobby tier (no pre-deploy hooks); PR previews share `sculpt-dev` Supabase instance; secrets never committed to version control
**Scale/Scope**: 3 environments (Production, Develop, PR Preview); 2 services per environment (backend, frontend)
